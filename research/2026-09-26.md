## Implementation and why the default changed

The new command is `graphy ingraph-repair`. Existing `seek`, canonicalization,
and enumeration paths are unchanged. There are three separately selectable methods.

### `counted` (default): an exact objective, a heuristic walk

For a fixed candidate F, let C range over distinct labelled edge-set copies
of F in K_n. Define

```
Q(H) = #{C: C is entirely red in H} + #{C: C is entirely blue in H}.
```

For each host edge e, let M_e count monochromatic copies containing e, and
B_e count mixed copies in which e is the only edge of its colour. Then,
for candidates with at least two edges,

```
Q(H xor {e}) - Q(H) = B_e - M_e.
```

This is exact; no independence assumption or sampling correction is involved.
A single traversal of copies with at most one wrong-coloured edge, in each
colour, computes Q and all these one-edge deltas. Pattern-twin permutations
are suppressed, and the remaining automorphism multiplicity is divided out.
Host automorphisms are NOT suppressed: their different edge sets must count.
Pattern isolates are implicit.

The walk chooses favourable deltas, forbids recently flipped edges for a
short tabu tenure unless they improve its best score, and permits random
moves on plateaux/local minima. Both additions and deletions are allowed.
It retains the lowest-scoring host. A zero score is still checked using the
existing, separately implemented embedding oracle in both colours.

The counting traversal checks the deadline internally. A partial count is
discarded, never interpreted as a small score or a refutation. Memory does
not grow with the walk length: no growing host/copy library is retained.

### `learned`: lazy NAE constraints

Every discovered edge-set copy must have both colours in a refuter. Store
that not-all-equal constraint, incrementally maintain violated constraints
and flip costs, and check the full embedding oracle whenever the bank is
satisfied. Random relabellings of the same host diversify the collected
witnesses; every witness is mapped back before storage. Host labels remain
fixed throughout a walk. `--max-constraints` bounds the bank's growth.

This began as a [WalkSAT-inspired repair experiment](https://www.cs.cornell.edu/selman/papers/pdf/02.cp.randomwalk.pdf),
but the final implementation uses net make/break costs, not the paper's
precise move rule. One witness at a time was much too weak. Batches helped,
but exact counting was much more successful on the controls below. The
learned variant remains available for comparison, not the recommended default.

### `neighbourhood`: exact bounded edit search

At a host with a monochromatic copy C, any refuter must change an edge in C.
Branch on those edges, without flipping any edge twice along a branch.
This covers every possible refuter within the requested Hamming radius,
though it need not explicitly enumerate every host in that ball.

Exact labelled-state memoization is safe here: the set of changed edges is
determined by the current host xor the starting host, hence so is the
remaining depth budget. A completed `neighbourhood-exhausted` result rules
out only that ball. A time/step limit rules out neither the ball nor global
refutability. The step budget bounds retained states; no nauty calls are
needed inside the search.

### Held-out rediscovery

The old library alone refutes none of the three held-out candidates in
`repair14-controls.txt`. Forty-eight two-second attempts per candidate,
preferring one-colour-free seeds, initially found no refuters. They produced
best scores 30, 2, and 18. Refining those best hosts with four-edit perturbations,
tabu tenure 3 and noise 0.2 rediscovered the third candidate's refuter:

```
candidate: 35598312519616
refuter:   1965200090121250692899562228
```

The successful walk took 163 flips, ended 33 edges from its perturbed start,
and took about 1.6 seconds in that run. Its initial near-miss came from
old seed `9386249291126194522481498`, not from the held-out answer. Both the
found host's complement and the known `19045246657205181093300321` have
the same `labelg` form: `MtPMEA{^@UayHzEz?`. The host has 46 edges and
8 automorphisms; its complement fits the existing 6+6+2 template.

The successful refinement can be replayed without clock-dependent budgets:

```sh
printf '35598312519616\n' | target/release/graphy ingraph-repair 14 /dev/stdin \
    --method counted --seeds 1559257376644154015456552500 \
    --random-every 0 --restarts 2 --perturb 4 --tabu 3 --noise 0.2 \
    --rng-seed 260908 --seconds 0 --steps 200
python3 research/verify_refutations.py research/repair14-rediscovery-2026-09-26.csv
```

The first walk hits its 200-step limit; the second reproduces the exact
refuter above after 163 flips. The three held-out candidates and the
rediscovery certificate are small preserved files in this directory.

The radius-six attempts all timed out; none exhausted its ball. The best
n=15 pilot score was 28; n=16's was 64. All 51 hosts from the counted
controls and held-out rediscovery were also checked against the 25 survivors;
none refutes a survivor. Earlier learned-method frontier pilots added
200 attempts / about 600 seconds, also without hits.

The broad n=14 seed run used 210 isomorphism/complement classes after merging
the libraries. Very short attempts from some copy-rich old seeds were
unproductive: 45 of 300 timed out before completing even one exact score.
This is why I recommend refining the saved hosts rather than simply
launching millions of two-second restarts from the old library.

For resource scale, the four-worker counted pilot used about 3.3 MiB peak
RSS and completed in 84 seconds; the comparable learned pilot used about
87.5 MiB. The final six-process refinement took 200 seconds for 1000 summed
attempt-seconds. The `/usr/bin/time` peak for this process tree is not an
aggregate memory measurement; individual counted workers are small.

## Suggested handoff

I would try a bounded longer *refinement* campaign first, not a huge learned
constraint bank. The following uses the preserved per-candidate checkpoints
and takes roughly **1.7–2.2 hours on eight otherwise available cores** if
all 25 candidates use their full budgets. Hits stop that candidate early.
This is an exploration budget, not a prediction of finding a refuter.

```sh
cargo build --release --features native
python3 scripts/refine_repair.py research/repair14-best-2026-09-26.csv \
    --method counted --keep 1 --restarts 32 --seconds 60 \
    --perturb 4 --tabu 3 --noise 0.2 --jobs 8 --rng-seed 2026092601 \
    > output/repair14-long-a.csv 2> output/repair14-long-a.log
```

Each restart result is flushed immediately. `saved_host` and `best_copies`
make unsuccessful attempts useful checkpoints. Subsequent refinements can
read both the old checkpoint and the new CSV; `--keep 3` selects up to three
distinct labelled best hosts per candidate (the Rust command then deduplicates
isomorphs/complements). Changing `--rng-seed`, trying `--perturb 8`, or varying
the tabu tenure tests different basins; none guarantees improvement.

The copied best hosts are compact, so growing Python `emitted` sets are not
part of this workflow. An interrupted walk loses its in-progress trajectory,
not previously completed CSV rows. Only `refuted` rows are certificates:

```sh
awk -F, 'NR == 1 || $4 == "refuted"' output/repair14-long-a.csv > output/repair14-long-a-certs.csv
python3 research/verify_refutations.py output/repair14-long-a-certs.csv
```

If there are no such rows, the verifier deliberately reports that there are
no certificates. A long negative run must not be promoted to a proof.

The most justified next algorithmic experiments, if this stalls, are
coordinated multi-edge moves in the counted walk and/or a proper SAT solver
on learned constraints.
The measured two-copy traps show why merely increasing single-flip patience
may be insufficient. Neither extension was implemented or assumed to work here.

## Validation and reproducibility

- Exact counts and every flip delta match independent permutation enumeration
  on random five-vertex cases, including patterns with isolates and symmetries.
- Incremental learned-bank counts, violated membership, and make/break arrays
  match full recomputation through random additions and flips.
- Exhausted radius-two balls match brute-force host enumeration at n=4.
- All three methods have repeatable step-limited traces.
- Independent Python verification accepted the 50 counted controls and the
  held-out rediscovery; the independent counter checked the best five n=14 scores.
- Python tests cover checkpoint selection and independent-copy enumeration.
- Native and pure-Rust builds, including the u64 representation, are tested.
  There is no new dependency, solver installation, C change, or unsafe block.
