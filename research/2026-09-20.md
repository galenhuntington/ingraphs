These are read-only analyses and bounded diagnostic experiments on the

and no new refutation is claimed. Times are single-run wall times on this

## A concrete structural neighborhood

Two hosts account for 4,758 assigned first-pass refutations:

| Label | Decimal encoding as stored in the output | Edges | Assigned first-pass hits |
| --- | ---: | ---: | ---: |
| P | 69274636055794157290400326140543072642271 | 68 | 2,725 |
| A | 339578443211886202644714276609037181443 | 64 | 2,033 |

P is isomorphic to the Paley graph on 17 vertices: on integers modulo 17,
join vertices whose difference is a nonzero square. This was checked by
constructing that graph and comparing `labelg -q` canonical forms. It is
8-regular; dreadnaut gives automorphism group order 136 and two unordered
pair orbits.

The four second-pass hosts have the following full automorphism data,
computed from dreadnaut generators using `edge_orbits`:

| Decimal encoding | Edges | Aut order | Pair orbits | Assigned hits |
| ---: | ---: | ---: | ---: | ---: |
| 41377471758585704277729230762219708385279 | 68 | 2048 | 10 | 8 |
| 43514935601184572303753577661615363428115 | 65 | 640 | 11 | 1 |
| 80775745122754900361149698012665340202239 | 68 | 32 | 12 | 1 |
| 13600909768723914875856808999002015038303 | 68 | 720 | 12 | 1 |

Call the first of these B. Both A and B consist of eight twin pairs and
one singleton; they have the same nine-cell quotient after relabeling.
In A all twin pairs are independent. In B four of them are edges.

More explicitly, map B's vertices 0,...,16 to these vertices in A's labeling:

    16, 0, 7, 1, 2, 3, 6, 4, 5, 8, 9, 10, 11, 12, 13, 14, 15

Then B is exactly A plus the four edges

    (0,7), (1,2), (3,6), (4,5).

These four pairs form a single orbit of Aut(A), verified from the
generators. Both automorphism groups have order 2048 and ten pair orbits.
Thus this is one orbit toggle, though it is four individual edge flips.
Since the edge counts differ by four, the minimum edit distance over
relabelings is exactly four (without identifying complements).

For each of the eight newly refuted candidates, A must already avoid F
in the red graph: A is a subgraph of the refuter B. The obstruction in A
is in its complement, and adding this matching destroys all blue copies
without creating a red one. This is a concrete instance of candidate-
directed repair.

This supports looking at twin-cell quotients, changes to cell sizes and
internal edges, and structured multi-edge moves. It does not prove that
every refuter lies near a highly symmetric core, nor that symmetry measures
how deep a graph lies in a region of refuters. A precise candidate-specific
notion of local robustness is the number of single-edge flips that still
refute the same F.

For the earlier 121-pair-orbit host
`168817111969725279296181501561201497884`, none of its 136 one-edge
neighbors has automorphism group order greater than two. So there is no
immediate one-edge move toward a larger automorphism group in that example.
Deleting vertex 16 recovers the known n=16 seed
`5156505040963437398004905597736732`, with automorphism group order eight
and 16 pair orbits. A more distant or different-order structural core is
not ruled out.

## The memory growth is an unbounded cache

`scripts/orbitals.py::generate` stores every distinct labeled emitted
integer in `emitted`. These remain reachable until generation ends.
`scripts/refuter_variants.py` has the same lifetime issue with its global
`seen` set. This is sufficient to explain large memory growth without
postulating a leak in the orbit computation.

A bounded probe consumed, without storing outputs in the caller, the first
one million outputs of

    generate(14, 35, 45, family="cyclic", max_orbits=29)

All checkpoints were still within the first accepted orbit partition:

| Emitted integers | `sys.getsizeof(emitted)` | Process peak RSS (KiB) |
| ---: | ---: | ---: |
| 100,000 | 4,194,520 | 19,524 |
| 300,000 | 8,388,824 | 32,284 |
| 1,000,000 | 33,554,648 | 89,760 |

A sampled n=14 graph integer occupied 40 bytes in addition to the set's
table. One million therefore cost about 70 MiB for table plus integers,
with observed peak process memory about 88 MiB. Table resizing also raises
peak usage. At hundreds of millions of unique outputs, tens of GiB are
plausible. The 267-million variation count and the orbital OOM are separate
runs, but both scripts have this retention pattern.

The union traversal itself uses a recursion stack linear in the number
of pair orbits. It need not retain previous graphs. Nevertheless, its
running time is exponential: 29 orbit bits admit up to 536,870,912 subsets
for one partition, before edge-count pruning. Removing the cache fixes the
avoidable memory growth, not this combinatorial running time.

Recommended change: an explicit streaming/no-global-dedup mode in both
scripts, preserving the old unique-output behavior when requested. Keep
the much smaller orbit-partition cache. Let `labelg -q` followed by an
external `sort -u` perform isomorphism deduplication, with an explicit sort
memory budget. Duplicate stream entries affect time, not the resulting
set of graphs. This mode is a proposal, not yet an implemented option.

## Candidate-directed starting points at n=14

For each of the 26 current candidates, both colors of all 207 entries in
`output/somes-14.txt` were checked with the current Rust subgraph matcher.
There were no refutations. However, each candidate had between 58 and 79
seed entries which avoided it in exactly one color. These counts are seed
entries, not a claim about distinct isomorphism/complement classes.

Orient the free color as red. Such a host is a legitimate starting point
for the existing monotone repair recursion: find a blue copy of F, add one
of its edges to red, and reject moves that create a red copy. Currently
`seek` always starts from the one-edge deletions of F, rather than from
these denser, structured hosts.

Seeded repair can reach beyond a fixed edit radius without enumerating the
whole Hamming ball. It is still a heuristic restriction: a particular seed
may have no refuting supergraph, even when a refuter exists elsewhere.
Allowing controlled deletions/restarts or using a lazy SAT formulation
would address this limitation. The latter would learn valid constraints
from red and blue copies and permit changes in both directions. The current
seek routine already uses the basic copy-guided branching idea; clause
learning would be the substantive addition, not merely using a copy as a
guide. No performance or existence claim is made for these proposed searches.

## Why the expectation bound is exact

Let N=binomial(n,2), and let F have m>0 edges, v nonisolated vertices,
and a automorphisms after deleting isolated vertices. There are
C=(n)_v/a distinct copies of its edge set in K_n. For each such copy i,
let I_i be its monochromatic indicator in a uniform random edge coloring.
Then

    P(I_i=1) = 2 * 2^(-m),
    E[sum_i I_i] = sum_i E[I_i] = C * 2^(1-m).

The second equality never requires independent indicators. If F is
universal, their sum is at least one in every coloring, so

    m <= 1 + log_2(C) <= 1 + log_2(n!).

Alternatively, each copy is monochromatic in exactly 2^(N-m+1) labeled
colorings. Covering all colorings requires 2^N <= C*2^(N-m+1), even when
the cover overlaps heavily. This is an exact finite counting inequality.

The user's information argument is also valid. Choose for each unlabeled
graph a labeling where a fixed template of F is monochromatic. Store the
N-m other edge bits and the common color bit. Decoding recovers a labeled
representative of the original isomorphism class. Different classes cannot
have the same code; no permutation needs to be stored because the target
is an unlabeled graph. There are at least 2^N/n! classes and at most
2^(N-m+1) codes, giving the same bound.

Unavoidability is stronger than this project's property, so its existence
theorems give lower bounds here, not upper bounds. The separate counting
argument is what supplies the upper bound. See the introduction of
[Bucic, Draganic and Sudakov](https://people.math.ethz.ch/~sudakovb/universal-and-unavoidable.pdf)
for the definition of (n,e)-unavoidability and the earlier dense-regime result.

The finite clique count used in `scripts/lower.hs` is sound: if r is a
valid upper bound for R(K_k,K_k), then n >= r+2k(q-1) permits extracting
2q-1 disjoint monochromatic k-cliques, guaranteeing q of one color.
Thus q=floor((n-r)/(2k))+1 for n>=r is valid. This checks the formula,
not an independent audit of all its tabulated Ramsey bounds.

## Canonicalization: objective and implementation both matter

Nauty chooses an isomorphism-invariant representative, not graphy's
globally minimum decimal representative. For arbitrary canonization,
ordered isomorphism-invariant refinements can restrict the labeling search
without losing canonicity; preserving a prescribed numeric minimum needs
additional justification for each such restriction. There is no need to
compute the numeric minimum merely to recognize duplicates.

There are also implementation costs in `src/enumerate.rs`: branch-local
permutation allocations and graph renumberings, symmetry pruning limited
to twins, a cutoff that is not tightened as `best` improves, and repeated
whole searches in `to_best` until no change occurs. The cutoff rows remain
those of the previous pass even after improving a more significant row;
this can defer lower-row improvements to later passes. Removing that loop
without redesigning the prefix/cutoff logic would not be a justified fix.

On the current 26-entry n=14 pool, the first phase of successors issues
1,924 raw extension requests (1,904 distinct labeled integers). There are
738 resulting isomorphism classes. On that identical graph6 input:

| Canonicalizer | Wall seconds |
| --- | ---: |
| `labelg -q` | 0.0126 |
| `graphy canon 14 /dev/stdin` | 0.1915 |

Recanonicalizing all graphy outputs with labelg matched the labelg outputs
of the inputs, entry by entry. The approximately 15-fold difference is for
this canon-only sample, not the entire successors command.

A temporary Python batch-labelg implementation of successors, with no
`--max`, took 0.4817 s including Python and process overhead. It tested
13,284 retractions and found the same one successor as the existing Rust
command, which took 0.6126 s. This is a correctness check and illustrates
why a canon-only ratio should not be advertised as an end-to-end speedup.

There is a further pre-canonicalization reduction: choosing one extension
edge from each orbit of the input graph's full automorphism group reduces
the 1,924 requests to 805. Final canonical deduplication is still needed:
different edge orbits can give isomorphic unmarked extensions.

A suitable implementation would expose an internal isomorphism key through
a small Rust-to-C wrapper around dense nauty, retaining minimum-decimal
canonicalization for output and existing order-sensitive operations.
At these graph orders an adjacency row fits in one machine word. Use
consistent nauty options, retain the vertex count including isolates,
and do not mix keys with legacy decimal labels in the same set.

The key sites are `seek.rs::recurse` and the extension/retraction membership
tests in `main.rs::successors` and `tools.rs::bump`. In particular,
`successors --max` compares minimum decimal values: it cannot use the new
key's numeric order. The canonical enumeration routines also rely on the
existing ordering and should not be globally switched over.

Nauty needs a thread-local-storage build for concurrent Rayon calls;
all relevant C objects, not just the wrapper, must use compatible options.
Its canonical output can depend on options and representation, so persistent
keys also need a fixed backend convention. These requirements are documented
in the [nauty 2.8.9 guide, sections 7 and 16](https://users.cecs.anu.edu.au/~bdm/nauty/nug28.pdf).
The repository already contains nauty sources used by `nauty-prune`, but
those existing object files should not be assumed safe for parallel calls.
