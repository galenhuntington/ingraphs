## Implementation

### Diverse seeds, bounded archives, and restart scheduling

`scripts/refine_repair.py` now obtains exact packed native canonical keys
for H and its complement **before** applying `--keep`. This uses the new
`graphy canon N FILE --internal-labels --complement`; ordinary `canon`
retains its least-decimal semantics. No external `labelg` process is needed.

`--archive K --archive-slack S` keeps up to K distinct classes whose score
is at most the current best plus S. Lower scores take priority; equal scores
are sampled using a deterministic per-walk ranking. The best visited host
is always saved separately. The archive uses full canonical graphs for
equality, not probabilistic hash equality, and never grows with walk length.
Canonicalization compares hosts but does not relabel a live walk. Archiving
does not consume the walk's RNG stream.

The helper carries selected input seeds into the new CSV, accepts current
survivor filtering (`--candidates`) and individual selection (`--candidate`),
and assigns **one restart per worker task**. A single-candidate campaign can
therefore use six workers. `--restart-offset` preserves the original RNG and
seed-selection schedule when splitting attempts, if the input seed pool and
other parameters are unchanged. The direct Rust command still parallelizes
candidates, not their restarts.

Selected seeds and old certificates are cross-checked before launching
walks. New refuters are shared across selected candidates. Future attempts
on refuted candidates are skipped; already running attempts finish, keeping
their checkpoints. The candidate files themselves are never modified.
Inputs, including pipes and `<(...)`, are read only once.

CSV `record` values distinguish `outcome`, `checkpoint`, `seed`, and
`cross-refutation`. Only `status=refuted` rows are certificates. Timing and
evaluation totals appear only on outcome rows; use `record=outcome` when
counting attempts or flips. `--prepare-only` emits a resumable seed pool
without launching walks.

### Preparatory single-edge moves

`--moves all` is now the default. It allows flips outside the union of
current monochromatic copies. Such flips cannot immediately decrease Q,
but they can be much cheaper ways out of a local minimum. Exact scores for
these edges were already computed, so no extra counting traversal is needed.
Tabu, aspiration, and noise remain in place. `--moves focused` reproduces
the old eligibility rule. Fixed-step traces with this setting were checked
against a saved pre-change binary.

### Exact paired moves

Let delta(e) be the exact single-flip change in Q. A traversal allowing at
most two wrong-coloured edges computes a correction K(e,f), with

```
Q(H xor {e,f}) - Q(H) = delta(e) + delta(f) + K(e,f).
```

For each colour and each copy C:

- Zero wrong edges: add +1 for each pair inside C (the single deltas would
  otherwise subtract the same copy twice).
- One wrong edge e: add -1 for each pair {e,f} with f another edge of C
  (flipping f as well cancels the copy created by flipping e).
- Exactly two wrong edges {e,f}: add +1 for that pair.
- All other cases contribute zero.

This is an exact finite-difference identity, including overlap between
copies; it assumes no independence. Contributions from both colours are
added, with the same exact pattern-automorphism multiplicity correction as
the single-edge counter. The pair table has 4,095 entries at n=14 and
7,140 at n=16: about 32 KiB and 56 KiB respectively. Extra traversal time,
not this table's memory, is the main cost.

`--pair-every K` tries a pair evaluation every Kth decision at which the
best allowed single move is non-improving. These decisions are counted
cumulatively, not necessarily consecutively. A pair is chosen only if its
joint score beats the best allowed single move; both endpoints obey tabu
unless the pair improves the best score. Pair moves consider all edges,
independently of `--moves`. The two flips count against the step budget.
Incomplete evaluations are discarded, and a refutation still requires the
separate two-colour absence oracle.

An important trap showed up immediately: the apparently best pair could
just swap labels of almost-twin vertices. Pair moves isomorphic, or
complement-isomorphic, to the current host are now skipped. Only zero-delta
pairs need this canonicalization check.

Here are exact, **host-specific** escape costs, with no tabu exclusions:

| Candidate | Host | Q | Best focused single | Best unrestricted single | Best genuine pair |
| --- | --- | ---: | ---: | ---: | ---: |
| `208095050752` | `149391117928587412994558940` | 2 | 10 | 8 | 3 |
| `35391346720704` | `1735057707038897413644043761` | 5 | 19 | 14 | 9 |
| `35391346720704` | `240446773475227354961364772` | 5 | 9 | 9 | 6 |

The two five-copy hosts are different classes; their escape costs must not
be mixed. These examples are covered by a regression test. Pair moves
lower the immediate barrier, but neither the score nor these escape costs
measure distance to a refuter. In particular, earlier radius-four exclusion
results are not contradicted by these moves.

## Suggested handoff

I would try one bounded, diverse n=14 paired campaign before committing to
another overnight run. This is a different experiment from lengthening the
old walk; it is **not a prediction that the remaining 25 are refutable**.

```sh
cargo build --release --features native

python3 scripts/refine_repair.py research/repair14-seeds-2026-09-27.csv \
    --candidates output/batches/all14 --keep 16 \
    --moves all --pair-every 8 --archive 16 --archive-slack 32 \
    --restarts 32 --seconds 20 --perturb 4 --tabu 3 --noise 0.2 \
    --jobs 6 --rng-seed 2026092706 \
    > output/repair14-diverse-next.csv 2> output/repair14-diverse-next.log
```

Expect about **45 minutes** on six workers if there are no hits and all
attempts consume their time budget: 25 * 32 * 20 / 6 seconds, plus small
startup/cross-check overhead. There are at most 16 classes per candidate,
so 32 restarts visits each selected seed at least twice. `--keep` is not a
restart count; each restart starts from one selected seed. Some n=14
candidates still have only one available class.

For a matched comparison, use the same input, root seed and parameters but
`--pair-every 0`, writing different output files. If neither gains ground,
I would investigate sparse adaptive penalties or bounded history over host
classes rather than simply scaling the duration. The unweighted zero and
independent absence tests should remain the certificate gate.

For n=15/16, the consolidated files can be used similarly. A conservative
next pass is `--moves all --pair-every 0 --keep 16 --archive 16 --restarts 16
--seconds 20 --perturb 4 --tabu 3 --noise 0.2 --jobs 6`, with distinct root
seeds and output filenames. Budget roughly **55 minutes for n=15** or
**28 minutes for n=16**. The evidence for paying the pair-counting cost is
currently stronger at the inspected n=14 minima than at larger orders.
