# Prepared matching and component packing

## What changed

The existence/witness matcher now lives in `src/matcher.rs`; the historical
`tools::{is_subgraph_of,find_subgraph_of,find_subgraph_ss,isso_inner,ingraph_check}`
entry points delegate to it. There is only one embedding implementation.
The SAT/counting oracle remains separate, including its final independent
existence checks.

Three immutable, owning types replace the order-only cache for bulk work:

- `PreparedPattern`: graph, adjacency masks, degrees, connected components,
  density-first matching order, and pattern twin predecessors.
- `PreparedHost`: graph, masks, degrees, components, descending-degree host
  order, and host twin predecessors.
- `PreparedColours`: a host and its complement, prepared together. The
  complement's masks are obtained directly from the original adjacency masks.

Each object owns a copy of its graph. Changing the original cannot make a
cache stale, and the types can be shared between Rayon threads. Degree/order
and twin indices use small integers; vertex masks remain `u32`, independent
of the packed-edge backend. Both graphs must have the same order; a smaller
pattern should be padded with isolated vertices before preparation.

For example, inside Rust:

```rust
let pattern = PreparedPattern::new(&candidate);
let host = PreparedHost::new(&graph);
let present = pattern.is_subgraph_of(&host);
let witness = pattern.find_subgraph(&host); // copy in host labels

let colours = PreparedColours::new(&graph);
let covered = colours.covers(&pattern); // present in at least one colour
```

Reuse `pattern` across hosts, and reuse `host`/`colours` across patterns.
Ordinary boolean queries no longer allocate a permutation merely to return
`true`. A witness still uses a permutation with the existing orientation.
At query entry, small cached arrays are copied into a local search frame and
indices are widened once. This preserves the compact library while avoiding
the inner-loop slowdown measured with borrowed arrays/narrow indices.

Integration points:

- `cull` prepares its fixed library once, shared by workers.
- `ingraph-seek` prepares library entries lazily, reuses them across candidates,
  and removes cached entries on expiry. Its timing-based refuter ordering is
  retained, but timings now measure matching rather than repeated preparation.
- `ingraph-check` prepares its single candidate once and streams hosts without
  retaining a growing cache.
- `seek`, `free-scan`, `free-close`, and learned/neighbourhood repair reuse a
  prepared candidate. Changing hosts are prepared afresh.

On this machine the u256 build uses **704 bytes per prepared two-colour host**,
without heap allocations inside that host pair. A 46,820-host library therefore
uses roughly 31.4 MiB of inline matcher data, excluding container overhead.
There is no cache proportional to the accumulated candidate stream.

The preparation API rejects edges outside the stated order, unequal query
orders, and stale legacy matching rows. Empty graphs work. The CLI's
order-inferred `is-subgraph` handles a pattern larger than the host as `false`
before preparation, including mixed-order matrices.

## Why the packing rejection is sound

The image of a connected pattern component is connected, so it lies wholly
inside one host component. Injectivity means the sum of pattern component
sizes assigned to any one host component cannot exceed its size. Multiple
pattern components **may share** a host component: this is non-induced
matching, so additional host edges are allowed.

We therefore solve the small size-only packing problem before embedding:
largest items first, skipping equivalent residual bin capacities, with exact
backtracking rather than greedy packing. Once only singletons remain, they
can fill the remaining slots. Connected hosts bypass packing entirely, since
the query orders agree. Insufficient total host edge count is also rejected.
Passing either check is not evidence of containment; the full matcher follows.

For the reported slow case:

```text
F = 1329268563080305633988669656996007944
H = 615220134502691169874691659634381667188743
component sizes: F = 10+7+1, H = 14+4
```

Both nontrivial components would have to use the 14-vertex host component,
but need 17 vertices. The new code rejects this at the root, without any
embedding backtracking. The complement **does** contain F, so H is not a
two-colour refuter.

This is a root precheck, not a residual-component analysis at every recursive
node. It fixes this obstruction, not all exponential matching cases. Query
timeouts have not been added, and the existing soft-limit caveats still apply.

## Colour ordering

For two-colour existence checks, run the cheap necessary checks first. Skip
impossible colours; if both remain possible, try the colour with more edges,
retaining complement-first order on ties. One positive answer suffices, while
a refutation still requires exact absence in both colours.

Density is a heuristic, not a theorem that this colour is always easier.
Single-colour/witness-driven searches retain their prescribed colour: notably
`seek` still needs the complement witness on which its recursion is based.

## Measurements

The reported individual n=18 negative query now takes about **3 ms including
process startup** (median of 15 invocations of the final SAT-enabled binary).
Its rejection is structural, not a fortunate fast backtracking trace. The
earlier multi-minute timing is the reported old behaviour, not a fresh full
rerun of the old slow query.

Single-worker `cull` timings, in seconds, with the pre-change u256 binary and
the new u256/native/SAT build; medians of three runs, including preparation
and output:

| Candidate corpus | Candidates | Library | Before | After | Survivors |
| --- | ---: | ---: | ---: | ---: | ---: |
| `output/g14a.csv` | 1,734 | 48 | 0.423 | 0.061 | 48 |
| `output/g15a.txt` | 2,606 | 17 | 3.537 | 2.754 | 2,133 |
| `output/g16b.csv` | 603 | 86 | 4.670 | 4.581 | 30 |
| first 5,000 of `output/sample-18-18b.g6` | 5,000 | 260 | 4.012 | 1.686 | 0 |
| `output/sample-18-18c.txt` | 10,000 | 260 | 14.303 | 6.223 | 31 |

The n=14/15/16 libraries are the ordered, deduplicated union of all `--seeds`
arguments in `proofs/14.sh`, `15.sh`, and `16.sh`, respectively. The n=18
library is `output/refuters-18-18.txt`. The comparison uses the existing
post-width-fix `target/release/graphy-u256`, **not** `graphy-u256.bak`.
Every compared `cull` CSV agrees byte-for-byte, including the first refuter,
not just the count. Treat the small n=16 difference as essentially neutral.

The final ordering-only benchmark on the 5,000-candidate n=18 prefix gave
median query times **2.592 s complement-first vs 1.695 s denser-first**,
with identical first-refuter vectors. Thus part of the gain is indeed the
colour choice, independently of preparing/caching the graphs. This is not
a prediction for every candidate/library combination.

Two larger smoke checks, one worker each:

- The full 105,995-line `sample-18-18b.g6` sweep against the 260 refuters,
  using `ingraph-seek --bailout 0 --expiration 0`, completed in **73.3 s**
  with **2,332 survivors**. The 2,390 in `pilot1818.log` is not a controlled
  before/after comparison: that command leaves the default expiry of 10,000
  candidates enabled. Timing-based ordering affects which library entries
  expire. Disabling expiry keeps the entire selected library available.
- `ingraph-check` of the troublesome F against **all 46,820** hosts in
  `output/orbitals-18.g6` did **not** finish within a 90-second diagnostic
  cap. It was terminated, and no completed result is claimed. The fixed
  individual query therefore does not imply that the full orbital scan is
  now cheap; the remaining cost has not been localized in this change.

## Validation

All release Rust tests pass with `u256,native,sat` (81), `native,sat` (76),
and `--no-default-features --features u64,sat` (75). Each configuration has
one intentionally ignored corpus benchmark. All **78 Python tests** pass
against the new wide SAT binary.

New checks cover exact packing against independent labelled-bin assignment
on small integer partitions; a successful packing requiring backtracking;
all labelled graph pairs through n=4 against permutation enumeration;
random relabelled pairs; twin-heavy positives at every supported order;
zero-order graphs; high-word edges and complements; stale/out-of-range
input rejection; the actual n=18 case and relabellings; sequential/parallel
`cull`; adaptive seed-only `ingraph-seek`; and cache expiry. Packing success
is also explicitly tested on a pair that does **not** embed.

## Reproducing tests and the colour-order comparison

The review build is kept separately from the existing release executables:

```sh
cargo build --release --target-dir target/matcher \
    --bin graphy-u256 --features u256,native,sat
cargo test --release --target-dir target/matcher --features u256,native,sat
cargo test --release --target-dir target/matcher --features native,sat
cargo test --release --target-dir target/matcher --no-default-features --features u64,sat
GRAPHY_BINARY=target/matcher/release/graphy-u256 \
    python3 -m unittest discover -s scripts -p 'test_matcher.py'
```

This session needed the existing `nix-shell -p rustPlatform.bindgenHook`
workaround for SAT builds: the plain environment's fallback libclang could
not load `libstdc++.so.6`. This required no source/build-system change.
Within that shell, `env -u NIX_ENFORCE_NO_NATIVE CFLAGS= cargo ...` allowed
the requested native compiler flags. A normally configured shell can use
the ordinary commands above.

The ignored corpus benchmark isolates colour ordering using exactly the same
prepared data, packing check and embedding engine. It checks equality of
every first-refuter result, not just survivor totals. It alternates timing
order across repetitions. Preparation and output are excluded from query time.

```sh
GRAPHY_MATCH_N=18 \
GRAPHY_MATCH_CANDIDATES=output/sample-18-18b.g6 \
GRAPHY_MATCH_HOSTS=output/refuters-18-18.txt \
GRAPHY_MATCH_LIMIT=5000 GRAPHY_MATCH_REPEATS=3 \
    cargo test --release --target-dir target/matcher --features u256,native,sat \
    benchmark_prepared_library -- --ignored --nocapture
```

Omit `GRAPHY_MATCH_LIMIT` for the full file. These are timing corpora, not
claims that a prefix is a representative random sample or a complete frontier.

## Campaign use

No new search flags are needed. For example, a repeat of the reduced-library
n=18 pilot uses:

```sh
RAYON_NUM_THREADS=1 target/matcher/release/graphy-u256 ingraph-seek \
    18 output/sample-18-18b.g6 --bailout 0 --expiration 0 \
    --seed-file output/refuters-18-18.txt
```

Start with the reduced library to check throughput, then revisit the full
orbital library if wanted. Keep stdout in a **new** result file if saving it.
This is a matcher change; it does not alter the sampling/whole-frontier plan
or make survivors into universality certificates.
