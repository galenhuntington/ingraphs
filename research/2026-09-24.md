# Native keys, streaming generation, and a bounded template experiment

Implemented on `codex-gen1`. No candidate lists or stored proof results were
modified. This report distinguishes internal canonical labels from graphy's
minimum-decimal labels, and throughput measurements from universality claims.

## Build and interface

`cargo build --release --features native` builds the new default nauty backend
with `-march=native`. Without `native`, the C code is CPU-generic. Release
already supplies `-O3` via `cc` and Cargo's `OPT_LEVEL`; Rust's target CPU is
unchanged unless the caller separately sets `RUSTFLAGS`.

The compiler here is `cc` from `/home/galen/.nix-profile/bin`, GCC 15.2.0,
not Debian's base compiler. The recorded release compiler command includes:

```text
cc -O3 -ffunction-sections -fdata-sections -fPIC -m64 -std=c11
   -I <generated-headers> -I <vendored-source>
   -march=native -DWORDSIZE=32 -DMAXN=32 -DUSE_TLS
```

The exact command is saved under
`target/release/build/graphy-*/out/nauty/compiler.txt`.
`CC`/`CFLAGS` overrides are honored; the same compiler and language flags
are used to configure headers and compile the library.

The old warnings were nauty 2.8.9/C23 noreturn-attribute diagnostics, replayed
by Cargo even when the build was fresh from cache. `cc::Build::warnings(false)`
disables its added warning flags, not every default compiler diagnostic.
The new build pins nauty 2.9.3 and explicitly uses C11 for configuration and
compilation. Two consecutive cached probe test runs emitted no warnings.

The bundled source is an unmodified subset of the upstream release, with
archive checksum and license notices in `vendor/nauty-2.9.3`. All 18 upstream
files were byte-compared against the downloaded release. Upstream configure
generates two headers in Cargo's OUT_DIR; `cc` builds five upstream C files
and the adapter as a static library. There are no build-time downloads,
bindgen/libclang requirements, or dependencies on the local nauty-prune tree.
The current native build supports native POSIX targets with a C11 compiler
and standard configure utilities. Cross-builds/non-POSIX targets can use
`--no-default-features` for the pure-Rust key backend.

The adapter takes arrays of 32 u32 adjacency rows and returns the canonical
rows. Rust validates the graph order and bits before entering C. All C objects
use the same TLS/word-size/maximum-order options. Keys are exact packed graph
integers, not hashes, and caches are fixed-order. Their labeling is not a
stable cross-version identifier; external input is always normalized.

The standalone probe now shares this build and adapter. Its obsolete duplicate
C shim was removed; its diagnostic CLI remains separate from graphy.

## Generator changes

The orbital generator now explicitly streams without its unused `emitted`
set. Only orbit partitions are cached. External `labelg -q | uniqg -cq`
deduplication is appropriate for heuristic libraries; `uniqg` uses SHA-256
fingerprints. The exact alternative after labelg is `awk '!x[$0]++'`.
Neither external cache is bounded-memory just because its output streams.

The shared graph6 encoder uses a 64-entry bit-reversal lookup table. It was
checked against the old implementation at every order 1..62. Median times
over three passes of 100,000 n=14 encodings were 2.192 s old versus 0.275 s
new, approximately 8x for encoding alone, not the entire pipeline.

`--family all` is useful at lower orbit caps: it adds larger layered actions
which can represent a graph with fewer orbits than any single cyclic action.
It is not necessarily a short run at the same high cap as a cyclic campaign.

## Successors and minimum-decimal output

`successors` normalizes its input into native keys, deduplicates extensions,
and rejects an extension at its first missing retraction. Arbitrary decimal
labels and graph6 input are accepted, including noncanonical geng output.
Default CSV output still uses minimum-decimal labels, but ordering can differ.
`--max` retains the legacy ordering-based implementation.

`--internal-labels` skips final minimum-decimal conversion for intermediate
stages. It conflicts with `--max`. `proofs/16.sh` uses it for the first three
successor stages and keeps minimum-decimal output at the last stage.

Median wall times of three small whole-command runs, against a release build
of the unmodified starting code:

| Input | Original | New native | Ratio |
| --- | ---: | ---: | ---: |
| all14 (25 graphs) | 0.608 s | 0.019 s | 32x |
| all15 (67 graphs) | 2.734 s | 0.054 s | 51x |
| all16 (33 graphs) | 2.110 s | 0.030 s | 70x |

All output sets matched, including their minimum-decimal labels. These gains
combine nauty, early rejection, and the output conversion improvement below;
they are not a pure canonicalizer-only comparison.

The four-stage proof workload starting at `output/g16a.csv` was also checked:

| Stage | Output classes | Wall seconds |
| --- | ---: | ---: |
| 1 | 16,730 | 32.04 |
| 2 | 7,728 | 17.19 |
| 3 | 2,639 | 6.22 |
| 4, minimum-decimal output | 603 | 2.45 |

Total: 57.91 seconds, with exactly the same 603 graph numbers as the existing
`output/g16b.csv`. A separate run with all four stages using internal labels
took 48.00 seconds. Timing varies with other local work; neither measurement
reran the many-hour original implementation. The user's earlier 1.5-hour and
250-second timings are useful context, not controlled measurements here.

An unexpected output bottleneck emerged during this test: converting those
603 native-labeled results using the old minimum-decimal canonicalizer took
99.20 seconds. Preordering vertices by decreasing degree first reduced that
conversion to 0.38 seconds, with the same answers. `enumerate::to_best` now
uses the smaller of the original integer and this cheap isomorphic relabeling
as its initial bound, then runs its existing exact search. This does not
assume that degree order is canonical or restrict any permutations. It just
starts with a better upper bound, particularly when nauty labels isolates
first. Existing least-decimal semantics are unchanged for all callers.

An earlier full-chain trial with minimum-decimal conversion at every stage,
before this improvement, hit a 180-second subprocess timeout in stage one.
That subprocess was killed and waited for by the runner; no benchmark job was
left running. The successful comparisons above used the completed implementation.

## Seek integration and realistic gains

Both `seek()` and the search phase of `ingraph-seek` use exact native keys.
The seed-library matcher phase is unchanged. Working graphs retain their
labels; only cache keys are canonicalized, and only a returned witness is
converted to minimum-decimal form. Root retractions retain their first
original representative, so backend choice does not alter root order.

`--rng-seed` with `RAYON_NUM_THREADS=1` permits repeatable traversal with
either backend. Parallel traversal remains scheduling-dependent. The shared
stop flag now also stops sibling branches when the state limit is reached;
previously those siblings could keep inserting states after a branch bailed
out. A finite-limit `None` is inconclusive, not a proof of universality.
The cap is soft by at most concurrent in-flight insertions; --bailout 0 still
skips search and preserves its existing output convention.

For a controlled backend comparison, each command was given one candidate,
no host seeds, --bailout 2000, --rng-seed 20260924, and one Rayon worker. The
pure-Rust fallback also includes the improved initial minimum-decimal bound.
Both backends followed the same seeded algorithm and returned `(None, 2000)`.

| n | Candidate | Pure-Rust key | Native key | Ratio |
| ---: | ---: | ---: | ---: | ---: |
| 14 | 208052533120 | 3.389 s | 1.808 s | 1.87x |
| 15 | 105761182022656 | 8.523 s | 5.276 s | 1.62x |
| 16 | 108192841602070528 | 21.646 s | 21.265 s | 1.02x |

These are single-run samples, not general speedup guarantees. Earlier samples
also showed little n=16 improvement. The remaining matcher/search cost can
dominate, and the original randomized seek used different working labels, so
equal cache budgets alone do not make an old-versus-new run comparable.
The native key is much cheaper in isolation, but this does not establish
an equal reduction in time to a refutation or exhaustive proof.

## Bounded 6+6+2 experiment

`scripts/template14.py` recognizes the template in a seed with arbitrary
labels and explores a capped breadth-first neighborhood. It uses two moves:

1. Toggle an edge of A and its corresponding edge in the complementary B.
2. Switch a checkerboard 2x2 in the bipartite cross graph, preserving degree 3.

Both preserve 45 edges and the twin pair. The recognition chooses the first
valid complement isomorphism, so this is one specified neighborhood per seed,
not all possible alignments and certainly not the whole template space.
Two moves can reach graphs differing in up to eight edges, beyond the earlier
distance-four arbitrary-flip campaigns.

Starting with the three hosts in `template14-seeds-2026-09-24.txt`, depth two
exhausted after 6,731 labeled graphs, below the 10,000 cap. Deduplication left
1,081 classes. None refuted any of the current 25 candidates. The generated
library is `output/template14-2026-09-24.g6` (an ignored, reproducible artifact).

Reproduce with:

```sh
python3 scripts/template14.py research/template14-seeds-2026-09-24.txt \
    --depth 2 --max-graphs 10000 --graph6 \
    | labelg -q | uniqg -cq > output/template14-2026-09-24.g6
target/release/graphy cull 14 output/batches/all14 output/template14-2026-09-24.g6
```

No general constraint solver or open-ended search was started. Changing
alignments, cross incidence templates, or doing candidate-directed repair
remains future work; this negative neighborhood result is not evidence that
all 25 survivors are universal.

## Validation

- 22 Rust tests pass under default nauty, native-tuned nauty, native+u64,
  pure-Rust default-width, and pure-Rust u64 builds.
- All 32,768 labeled n=6 graphs induce exactly the same 156-class partition
  under native and legacy keys; random relabeling/idempotence/edge-count
  checks cover every supported order, with eight-thread stress checks.
- Successors match the legacy definition on complete and partial edge-level
  pools through n=6, including randomly relabeled inputs.
- Exhaustive seek agrees with independent permutation containment checks on
  every unlabeled graph through n=5, with one and four workers. Returned
  witnesses are checked in both colors and for minimum-decimal form.
- 13 Python tests pass, covering graph6, streaming, orbital generation,
  variants, template recognition, move invariants, reversibility and caps.
- Three standalone probe tests pass; two consecutive cached runs are quiet.
- CLI checks cover raw geng graph6, default/internal successor output and
  four --max cases against the original executable.
- The complete four-stage n=16 successor result matches the stored 603 graphs.
- `bash -n proofs/16.sh` and `git diff --check` pass.
