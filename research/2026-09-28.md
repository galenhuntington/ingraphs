## Scope and interpretation

This session tests two independent ideas: bounded adaptive copy penalties,
and candidate-specific seeds from the old `free-close` campaigns. Neither
failure to find a witness nor a positive minimum copy count proves
universality. Survivor lists and proof scripts are not modified.

Let Q(H) count distinct copies of F in H plus those in its complement.
Q is an exact objective, but **not an edit distance**. The earlier n=14
two-copy example already had no refuter within edit distance four. A walk
can repeatedly enter the same small collection of attractive regions even
when the full graph space contains refuters. More restarts of essentially
the same local search are not independent, uniform trials over that space.

## Adaptive penalties

The motivating idea is the constraint weighting in Morris's
[Breakout method (1993)](https://cdn.aaai.org/AAAI/1993/AAAI93-007.pdf):
raise the cost of currently violated constraints at a local minimum.
The original paper itself does not give general completeness for ordinary
Breakout. Our capped, smoothed, noisy/tabu variant has no such guarantee
either, and results on other constraint problems do not establish its
effectiveness here.

Each labelled copy C of F is an NAE constraint: its edges must not all have
one colour. All copies retain their unit weight in the exact counter.
The bounded memory adds an extra nonnegative weight w(C) to selected copies:

```
W(H) = Q(H) + sum_C w(C) * [C is monochromatic in H].
```

The extra single-edge delta is exact: a violated C contributes -w(C) on
each of its edges; a mixed C contributes +w(C) on its sole edge of either
colour, if that colour has exactly one edge. The two-edge-constraint case
can contribute on both edges, and is tested explicitly.

With `--penalty-every 1`, each non-improving **weighted** decision boosts
up to `--penalty-batch 64` distinct current copies per colour. These are
the first distinct copies visited by the counter, not a uniform sample;
restart relabelling changes that order. `--penalty-step 1` is the extra
weight per boost. `--penalty-cap 4096` bounds the number of remembered masks,
with FIFO eviction, and `--penalty-decay 64` halves the extra weights every
64 updates, dropping zeros. Decay zero disables smoothing. Individual
weights saturate at 1,000,000. No live host is canonicalized or relabelled.

Only move selection is weighted. Raw Q still determines the best host,
archive eligibility, tabu aspiration, and success; zero still passes the
separate existence matcher. Incomplete traversals yield no score and no
penalty update. The CSV adds `penalty_updates` and `penalty_constraints`
(final memory size); checkpoint/seed rows have zero diagnostic totals.

The option is off by default and currently requires counted single-edge
search (`--method counted --pair-every 0`). It does not silently substitute
approximate pair scores. Both Python helpers forward its five parameters.

## The free-close seeds

The old files are headerless `host,edges,complement_contains_F,display` rows
under `output/runsN/F-*/found-*.csv`. Initial seeds in `free-close` were
assumed F-free, so the importer rechecks that property instead of trusting
the old output. All surviving-candidate rows inspected had `true` in the
third column; no overlooked `false` certificate was found.

`scripts/free_close_seeds.py` preserves the candidate association and
original host orientation. It samples each density layer, deduplicates
exact isomorphism/complement classes, then ranks by complete copy counts.
Timeouts are omitted, never treated as zero. The output can be passed
directly to `refine_repair.py`; provenance, edge counts and separate colour
counts are included. `--per-layer 0` takes every raw host, and `--keep 0`
exports all completed valid scores.

`graphy ingraph-count N F HOSTS` supports this screening. It uses zero-wrong-
edge traversal rather than the repair evaluator's one-wrong-edge traversal:
we need counts, not every flip delta. Red and blue counts are separate;
zero results are additionally checked by the existence matcher. The clock
budget is **per host**, and incomplete counts are blank. Parallel output
ordering is unspecified.

0.25-second limit, and three/two workers for n=14/15:

The user's example `19338383731413630697207659`, for F=`482968729600`,
has **0 red and 9,600 blue copies**, despite its 56 edges. A sampled
46-edge host for the same F has only 898 blue copies; the current repair
best is 24. Across all sampled targets, the best free-close score was worse
than the existing repair minimum.

There is no monotonicity paradox: **along an F-free edge-addition chain**,
complement copies can only disappear. But unrelated maximal F-free hosts
need not be comparable by inclusion, and more edges need not mean fewer
complement copies. Also, a monochromatic-copy total alone cannot identify
the basin containing a refuter. These are three distinct seed criteria:
raw score, structural diversity, and how repair behaves from that seed.

Free-close experiments therefore use **only** the new seed pool, without
perturbation. Mixing it immediately with old low-Q seeds would discard
most of the new material at the `--keep` selection stage. Four restarts
visit at most four selected classes per candidate, not all 16.

After repair, the free-close n=14 run contributed 131 new classes within
32 copies of the old global minimum, across four candidates, compared
with the full latest user archives (not just their selected 16 seeds).
The n=15 run contributed two such classes for one candidate. Thus the
data really does add useful near-miss diversity, even though it did not
improve any minimum in these short experiments. High-scoring novel classes
are not included in these two counts.

## What to try next

I would not launch another blanket overnight increase in restarts. The
weighted n=15 gain warrants a **small focused follow-up**, not a claim
that the remaining cases will yield to weighting. The new six-class
Q=12 pool survived twelve additional 20-second weighted attempts at Q=12.

An optional four-minute experiment on six workers is:

```sh
python3 scripts/refine_repair.py research/repair15-seeds-2026-09-28.csv \
    --candidate 105898625070080 --max-score 16 --keep 8 \
    --restarts 48 --seconds 30 --perturb 0 --jobs 6 \
    --penalty-every 1 --penalty-step 4 --penalty-decay 128 \
    --archive 16 --rng-seed 2026092809 \
    > output/repair15-weighted-next.csv 2> output/repair15-weighted-next.log
```

Budget: 48 * 30 / 6 = 240 seconds, plus startup/cross-check overhead, if
there are no hits. Here `keep` means starting classes, `restarts` means
attempts, and the memory resets each attempt. No initial perturbation is
needed to activate the weighted escape rule. Use a new root seed/output
filename for another independent campaign; don't repeatedly run the exact
same command expecting new RNG streams. For a matched comparison, replace
`--penalty-every 1` by `0` and use distinct output files. A continued plateau
would be a reason to stop spending more runtime on this particular setup.

For a substantive next implementation, especially n=14, I favor **SAT-based
block repair** rather than another single-flip parameter sweep. It is not
implemented in this session; no SAT dependency is installed here.

The concrete subproblem is to freeze most host edges and let, say, 24–40
edge variables change jointly. Choose the free block to hit every current
monochromatic copy, then expand it with edges involved in likely repair
conflicts. For every discovered copy C, both clauses are necessary:

```
(OR over e in C of x_e) AND (OR over e in C of NOT x_e).
```

An incremental solver proposes an assignment; the full graph matcher
either accepts it or supplies another violated copy and its clauses.
This avoids materializing every copy in advance and can cross a barrier
requiring many coordinated flips. A refuter still passes the independent
absence check. If the solver proves the restricted instance unsatisfiable,
that rules out **only that fixed-outside block**; a timeout proves nothing.
It would be a genuinely different local search mechanism, not a promised
solution to the full n=14 problem. A tested solver backend is preferable
to writing a new SAT engine for this experiment.

The old free-close data remains worth retaining as a separate diversity
source, especially the newly repaired near-misses already consolidated in
the September 28 seed pools. Its raw dense hosts are not, on this evidence,
better default seeds than the low-Q checkpoints.
